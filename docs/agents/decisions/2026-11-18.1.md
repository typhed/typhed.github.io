## Context

The repository is built with more than one AI coding assistant, and each contributor works with the tool of their
choice. Every tool reads its own folder and file names: Claude Code reads `CLAUDE.md` and `.claude/`, while many other
tools read `AGENTS.md` from the repository root. Instructions, agents, skills, and hooks kept in one tool's files stay
invisible to every other tool. Copying them into each tool's folder would leave several sources to keep in step, against
the rule that a value lives in one place. No shared format exists for hooks either, since each tool keeps its hook
config in its own file.

## Decision

The repository keeps one vendor-neutral harness, and each tool reaches it through its own entry point:

  * `AGENTS.md` holds the instructions every assistant shares. `CLAUDE.md` imports it and adds only what belongs to
    Claude Code.
  * `.agents/` holds the agents, skills, and hook scripts, and `SKILL.md` indexes the skills. A skill for one app lives
    in `apps/<app>/.agents/skills/`.
  * A tool's agents and skills folders are relative symlinks into `.agents/`, such as `.claude/agents` and
    `.claude/skills` for Claude Code.
  * Each tool registers the hook scripts in its own hook config by their `.agents/hooks/` path, so the scripts need no
    link.
  * The project memory and the harness notes live in `.claude/MEMORY.md` and `.claude/docs/`, and `AGENTS.md` sends
    every assistant to them.

## Consequences

  * An agent, skill, or hook is written once, and every wired tool picks it up through its links.
  * Wiring a new tool adds links and hook registrations, never a copied file.
  * A checkout needs Git's `core.symlinks` set to `true`, and on Windows, Developer Mode or an elevated shell. Otherwise
    each link checks out as a plain text file and the tool finds no agents or skills.
  * The agent files keep Claude Code's frontmatter keys (`model`, `tools`, `color`), the format they were written for.
  * A hook script reads one tool's event format, so registering it with another tool means checking that tool's input
    first.
