What this repository does: it builds three static Next.js 16 sites from one shared brand, shell, and auth layer in
`packages/`. They are the brand hub `typhed.com` (`apps/web`), the trading tools `trading.typhed.com` (`apps/trading`),
and the MDX blog `blog.typhed.com` (`apps/blogging`). The trading site parses a visitor's own market data in the browser
and runs charting, risk, sizing, backtest, and Monte Carlo tools on it. Nothing is uploaded.

## Audit Findings And Suggested Changes (Ranked)

19 findings, most important first, numbered across the three groups so a reply can say "fix 2 and 5". About ten
smaller ones are left out; they are listed after finding 19.

### Must Fix

#### 1. Excel Dates Shift By The Visitor's Time Zone

  * **Target Path(s):** `packages/chart-engine/src/parse/xlsx.ts:23`
  * **Current Behavior:** Resolved. `parseXlsx` passes `UTC: true` to `sheet_to_json`, so a date cell reads as UTC in
    every time zone, as a CSV time does; a test forces `Asia/Kolkata`.
  * **Issue / Bloat:** The engine promises that the same file yields the same candles on every machine, and reads a time
    without a zone as UTC; CSV uploads follow that rule. Measured with xlsx 0.20.3, an XLSX cell `2024-01-02 09:15`
    becomes `09:15Z` on a UTC machine, `03:45Z` in India, and `14:15Z` in New York. A date-only cell lands on
    `2024-01-01T18:30Z` in India, so every daily bar moves to the previous day. The same data as CSV and as XLSX draws
    two different charts.
  * **Suggested Change:** Pass `UTC: true` to `XLSX.utils.sheet_to_json`, which reads date cells as UTC in every time
    zone. Add a test that forces a non-UTC zone, such as `Asia/Kolkata`, and expects the UTC instant `09:15Z`.
  * **Expected Risk / Impact:** One option. XLSX charts move to the documented UTC reading; saved analyses keep the
    candles they stored. Skipping it leaves every Indian visitor's XLSX candles 5 h 30 min early. Once it lands, upload
    a real broker XLSX export and confirm that the candle times match its cells.

#### 2. Blog Dates Break The Time Tag And The Open Graph Date

  * **Target Path(s):** `apps/blogging/lib/posts.ts:90`, `apps/blogging/app/page.tsx:7`,
    `apps/blogging/app/blog/[slug]/page.tsx:48,60`
  * **Current Behavior:** Resolved. `toMeta` turns the frontmatter date into its `"yyyy-mm-dd"` string, both pages use
    one `formatPostDate()` from `lib/posts.ts` with `timeZone: "UTC"`, and a Vitest suite covers the loader.
  * **Issue / Bloat:** The built pages show the damage. The Open Graph tag is
    `<meta property="article:published_time" content="[object Object]"/>`, so link previews and search engines get no
    publish date. The `<time>` tag gets `dateTime="Mon Jul 13 2026 05:30:00 GMT+0530 (India Standard Time)"`, which is
    not a valid HTML date and changes with the build machine's time zone. Built on a machine west of UTC, the visible
    date reads a day early.
  * **Suggested Change:** Convert the date once, in `toMeta`, to its `"yyyy-mm-dd"` string. Move the helper into
    `lib/posts.ts` as one `formatPostDate()` with `timeZone: "UTC"` and import it on both pages. Add a small Vitest
    suite for the loader, which has no test, and list it with the other suites in the docs.
  * **Expected Risk / Impact:** The visible text stays `July 13, 2026`. Only the broken attribute and meta values
    change, to `2026-07-13`, and the sitemap's `lastmod` stays the same.

#### 3. Sidebar Tool Links Do Not Switch The Workspace View

  * **Target Path(s):** `apps/trading/components/workspace.tsx:87-95`, the trading sidebar in
    `packages/brand/properties.json`
  * **Current Behavior:** Resolved. A `ViewFromUrl` child reads `?view=` through `useSearchParams()` inside its own
    Suspense boundary and applies every change; a missing or unknown view is the chart.
  * **Issue / Bloat:** Next.js keeps a page mounted when only its query string changes. A visitor already in the
    workspace with data loaded clicks "Monte Carlo Lab": the address bar changes and the view does not. The link works
    only when the workspace mounts fresh.
  * **Suggested Change:** Read the parameter with `useSearchParams()` in a small child component inside
    `<Suspense fallback={null}>`, and apply each new value to the view; a missing or unknown `?view=` means the chart,
    so the "Workspace" link and the Back button return to it. The boundary keeps the static export building and keeps
    the rest of the workspace pre-rendered. Wrapping the whole workspace instead would drop it from the pre-rendered
    HTML, and turning the links into full page loads would throw away the visitor's loaded data.
  * **Expected Risk / Impact:** About 20 lines in one file. With a Clerk key, as in production, the pre-rendered HTML
    does not change, because the sign-in gate renders its loading state at build time. The sidebar still highlights
    "Workspace" on these links; finding 17 covers that.

#### 4. The Budgeting Page Uses Yesterday's Date After Midnight In India

  * **Target Path(s):** `apps/trading/components/budgeting/mnws/mnws-dashboard.tsx:39`,
    `apps/trading/components/tools/ipo/ipo-dashboard.tsx:31`, `apps/trading/lib/budgeting/mnws/io.ts:61`,
    `apps/trading/lib/ipo/io.ts:100`
  * **Current Behavior:** Resolved. `localIsoDate()` lives in `apps/trading/lib/utils.ts`, and both dashboards and both
    file-name fallbacks call it.
  * **Issue / Bloat:** One rule, applied two ways. Between 00:00 and 05:30 IST on the 1st of a month, the budgeting plan
    stops a month short, and its export file is named with the previous day.
  * **Suggested Change:** Move `localIsoDate()` into `apps/trading/lib/utils.ts` and call it from both dashboards and
    both file-name fallbacks. A test of the helper alone does not guard the call sites, so check each one in review.
  * **Expected Risk / Impact:** Four call sites. Nothing changes outside that window.

### Nice To Have

#### 12. A Fractional Cut-Off Price Can Lose A Whole Lot To Rounding

  * **Target Path(s):** `apps/trading/lib/ipo/applications.ts:145`
  * **Current Behavior:** Resolved. Total mode divides in whole paise, so a ₹1.10 cut-off with a 13,000-share lot keeps
    its lot; a test covers the case.
  * **Issue / Bloat:** That product is a float. A ₹1.10 cut-off with a 13,000-share lot gives `14300.000000000002`,
    so a corpus of exactly ₹14,300 floors to zero lots. Whole-rupee prices, the usual case, are exact.
  * **Suggested Change:** Divide in whole paise: round both amounts to paise first. Add a test with the case above.
  * **Expected Risk / Impact:** Same result for every whole-rupee price.

  * **Current Behavior:** Resolved. The README names the real package, `@typhed/entitlement-gate`.

#### 16. The Fixed-Parameter Monte Carlo Runs On The Main Thread

  * **Target Path(s):** `apps/trading/components/tools/monte-carlo.tsx:19-33`
  * **Current Behavior:** Resolved. The inputs settle for 400 ms before the run, the card reads only the settled run,
    and a `shortcut:` comment names the main-thread cost at the cap.
  * **Issue / Bloat:** The page freezes while it runs. Measured in headless Edge, typing "2000" into Trades / path and
    "20000" into Paths takes 2,848 ms, with long tasks of 149, 111, and 1,260 ms. The two neighbouring Monte Carlo tools
    already debounce into the worker.
  * **Suggested Change:** Let the inputs settle for 400 ms before the run, as the two neighbouring tools do. A debounce
    keeps the card's look and its instant first render; routing the run through `useSimulation` would add a request
    kind and a loading state that change the card.
  * **Expected Risk / Impact:** The same keystrokes cost one run of about 1,248 ms after typing stops, and the numbers
    stay the same. One run at the cap still blocks the main thread; name it in a `shortcut:` comment, and move it to the
    shared worker if phones stall at large inputs.

#### 17. The Sidebar Highlights "Workspace" On The Tool Links

  * **Target Path(s):** `packages/ui/components/product-sidebar.tsx:86`
  * **Current Behavior:** `isActive` returns false for any link with a query string and compares only the pathname.
  * **Issue / Bloat:** On `/?view=montecarlo` the "Workspace" link carries `aria-current="page"` and "Monte Carlo Lab"
    does not, so sighted and screen-reader users both get the wrong current page.
  * **Suggested Change:** Reading the query in the shared sidebar needs `useSearchParams` and a Suspense boundary in the
    shell, which would drop the sidebar from the pre-rendered HTML. The cleaner fix is a route per tool
    (`/tools/ema-lab/`), which is a product decision.
  * **Expected Risk / Impact:** Waits for the owner to choose between `?view=` links and a route per tool. The same
    choice settles a second case that remains after finding 3: when a visitor switches tabs inside the workspace and
    then clicks the sidebar link for the view already in the address bar, nothing changes, because the URL does not
    change.

#### 18. Web And Blog Copy Their Robots And Manifest Routes

  * **Target Path(s):** `apps/web/app/robots.ts`, `apps/blogging/app/robots.ts`, `apps/web/app/manifest.ts`,
    `apps/blogging/app/manifest.ts`
  * **Current Behavior:** Resolved. Both apps' robots and manifest routes return `buildRobots(property)` and
    `buildManifest(property)` from `@typhed/ui/lib/metadata`; the blog's manifest carries `purpose: "any"`.
  * **Issue / Bloat:** Two copies of each, already drifting, so a rebrand has to find and edit both.
  * **Suggested Change:** Add `buildRobots(property)` and `buildManifest(property)` to `@typhed/ui/lib/metadata`,

#### 19. The Python Checks Trip Over Windows And `pytest`

  * **Target Path(s):** the `gen:fixtures` scripts in `packages/chart-engine/package.json` and
    `packages/risk-toolkit/package.json`, `packages/analytics-python/test_analytics.py`
  * **Current Behavior:** Resolved. Both `gen:fixtures` scripts run Prettier on the fixtures, and each analytics check
    loads the module itself with bytecode writing off, so the script and `pytest` run the same three checks.
  * **Issue / Bloat:** `json.dump` lays arrays out differently from the committed Prettier format, so every regeneration
    shows a diff on unchanged values and fails `pnpm format:check` until someone runs Prettier. On Windows the two CSV
    fixtures also come out with CRLF endings, which git normalises away, so their diff is empty. `pytest` reports three
    errors on the analytics test, because its `test_*` functions take an argument that `pytest` reads as a missing
    fixture, and every run writes `apps/trading/public/py/__pycache__/`, which the next local build copies into the
    export.
  * **Suggested Change:** Run Prettier on the fixtures inside `gen:fixtures`, so a regeneration reproduces all eight
    JSON fixtures byte for byte. Let each analytics check load the module itself, and switch off bytecode writing before
    the module runs. The CSV endings can wait until either generator is next edited.
  * **Expected Risk / Impact:** Tooling only; the fixture values and the oracle's checks stay the same.

## Notes For Applying The Fixes

  * Validate every fix the same way: a targeted test that fails without the fix and passes with it, then every gate
    fresh with `TURBO_FORCE=true`, a comparison of the three exports against the current build, and a browser check.
  * The build comparison masks only what changes on every build (the build id, the content-hashed chunk names, and the
    sitemap timestamps), then compares every exported page's markup, every inline script, and every CSS rule. Two clean
    builds of the current code compare identical, so any difference it reports is real.
  * A push to `master` deploys the sites, so apply the fixes on a branch and merge only after review and after step 1 of
    the [go-live checklist](../../../../.claude/docs/tasks/cloudflare-cutover.md).
  * The fixed-parameter Monte Carlo sits behind the Pro gate, which a build without the Clerk key keeps locked. To time
    it, serve the export from a scratch server outside the repository that swaps the free-tier literal for `"pro"` in
    the one chunk it serves, rather than change code or config for a test.
  * Drive browser checks with `puppeteer-core` installed in a scratch folder outside the repository, pointed at the
    installed Edge or Chrome, as the trading app's `verify` skill describes. A Windows build logs prefetch 404s that a
    Linux build does not; see [owner-machine-checks.md](../../../../.claude/docs/tasks/owner-machine-checks.md).
